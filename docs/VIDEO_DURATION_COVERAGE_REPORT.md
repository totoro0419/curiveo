## 実行した取得経路と出典

- [公式IFrame Player API](https://developers.google.com/youtube/iframe_api_reference) の `getDuration()` がCuriveoの再生位置スライダーmaxと全長表示に反映されることをコードと実画面で確認。
- 正規の公開Curiveoのプレーヤーを読み込み、読み込み完了後の正整数max、iframe srcの元動画ID、全長表示を照合。再生/媒体ダウンロード/YouTube内部ページ解析を行わない。
- 全授業一覧の2,322 IDとローカルの収集順をSHA-256照合: `7ecd2990e10bb52fc13f6226ef7f34e012ce3c076986509f9d71cf889183d3dc`。数値とIDの対応をバッチ範囲・件数・重複検査で固定。
- `iframe-observation-batches.json` が実行した640本の秒数と確認日時を保持。`iframe-collection-queue.json` がそのID集合を保持。
- 旧証拠の残りにはwatch URLの個別metadata、元renderer videoIdをキーにしたplaylistラベル、元IDと秒数が一致するcheckpointがある。タイトルや位置だけで紐付けない。
- 動画ファイルの取得、APIキー公開、有料契約、制限回避を行わない。

## 更新・保存

- `npm run durations:collect`: 文書化されたYouTube Data API。秘密変数 `YOUTUBE_API_KEY` を実行環境のみで使用し、50 ID以下・逐次リクエスト。正整数ISO時間、要求ID/応答ID一致、ライブ未確定、取得失敗、競合候補を管理。キー不足時は値を捏造せず停止。
- `scripts/collect-iframe-in-browser.js`: キーなしの正規Player UI経路の再利用可能な収集関数。バッチ毎に結果を保存し、取得済み位置から再開する。
- `scripts/import-iframe-duration-observations.py`: SHA-256・ID集合・バッチ範囲を検査して候補保存。確認後に `--apply-reviewed` で採用。旧証拠と差分を保持。
- `scripts/review-legacy-duration-evidence.py`: 承認された重点監査方針で元のID付き証拠を審査。元の取得日時を30日の期限起点に使い、審査日を新しい取得日と偽らない。
- 同一チェックアウトの収集/採用/審査に共通カーネルロック。ファイルは一時ファイル経由の原子的置換。既存値の通信エラーによる消失を防ぐ。
- [Developer Policies](https://developers.google.com/youtube/terms/developer-policies) の保存・更新・データ利用条件を確認。取得日基準の `refreshBy` を管理し、期限切れは現在確認済みのデータとして表示しない。以後30日以内の再取得/更新が必要。規約の集約・派生値に関する一般条項の適用解釈について、YouTubeから個別の許諾を受けたとは称さない。

## 本番データと集計

- 本番は `video-durations.json` と軽量な `duration-status.json` だけを参照。詳細監査JSONはバンドルしない。
- 日本史補完ファイルは移行証拠として保持し、実行時には読まない。
- 元動画IDをグループ内で重複排除し、採用した整数秒を加算して最後に時分秒へ変換。視聴時間・チャプター開始位置は混ぜない。
- 正式メタデータは端末の古い記録より優先。0・小数・負値の端末値を拒否。欠損/未採用/期限切れを含む場合は部分値を確定した合計と呼ばない。
- `acceptedTotalSeconds` と `independentlyReverifiedTotalSeconds` を区別。後者は今回プレーヤー照合した動画のみで構成されるグループ以外null。
